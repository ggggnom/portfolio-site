# Правила вайбкодинга портфолио-сайта

> Черновик для Claude Code. Отредактировать под финальные значения (px, ms, easing) перед стартом.

## 1. Брейкпоинты и адаптив

- Три адаптива: **Desktop 1680px**, **Tablet 860px**, **Mobile 390px** (значения — референсная ширина макета в Figma, не обязательно `max-width` медиа-запроса один в один — уточнить у дизайна точки переключения).
- На **Tablet (860px)** и **Mobile (390px)**:
  - Меню зафиксировано снизу экрана (`position: fixed`, `bottom: 0`).
  - При нажатии на меню появляются якорные ссылки по разделам страницы (выпадающая панель/шторка со списком якорей — уточнить анимацию появления: снизу вверх / fade).
  - Клик по якорной ссылке — плавный скролл (`scroll-behavior: smooth` или через JS) к нужному блоку, после чего меню сворачивается обратно.
  - Предусмотрен **горизонтальный скролл** для некоторых блоков (см. макеты Figma для конкретных секций, где он есть — например, кейсы или сетка мелких изображений). Уточнить: горизонтальный скролл — на весь блок или только на его часть (карусель), и нужен ли свайп на тач-устройствах.
- На **Desktop (1680px)** — обычный вертикальный скролл, без нижнего меню (навигация в хедере, как на текущих макетах).
- Stroke слева (см. п.2) и фиксированный фон (см. п.3) должны сохраняться на всех трёх адаптивах, с адаптацией отступов под ширину экрана.

## 2. Общая структура страницы

- Весь основной контент на десктопе центрирован в блоке фиксированной ширины **940px**.
- У этого центрального блока есть тонкий серый stroke (вертикальная линия) по левому краю.
- Stroke идёт **через всю высоту страницы**, а не только в пределах одной секции — то есть это не декор одного блока, а сквозной элемент лейаута всех секций.
- На мобильной версии stroke сохраняется (не отключать, адаптировать положение под мобильный контейнер).
- Реализация: либо один `position: relative` контейнер на всю высоту страницы с псевдоэлементом `::before` (border-left / линия), либо отдельный fixed/absolute элемент-линия, растянутый на `100vh`+ высоту контента.

## 3. Фиксированный фон

- На фоне есть белое графическое изображение (декоративная форма, видна на первом экране).
- Это изображение должно быть **зафиксировано** (`position: fixed`, `z-index` ниже контента) и находиться **позади всего контента** на всех секциях страницы — то есть не скроллится вместе со страницей, всегда на своём месте.
- Контент должен иметь `z-index` выше, чтобы фон не перекрывал текст/картинки.
- Важно: проверить performance на мобильных (fixed-фон иногда дёргается при скролле на iOS — если будет лагать, обсудить fallback на `background-attachment` или отдельный слой).

## 4. Анимация появления зелёных кружочков

- Зелёные кружочки (декоративные точки) есть в начале сайта (hero) и в конце (вокруг фото).
- При появлении на экране (scroll into view) кружочки должны анимированно "проявляться" — например, поочерёдно (stagger), с лёгким fade-in + scale-up от меньшего размера к целевому.
- Триггер анимации — попадание блока в viewport (Intersection Observer), не автозапуск при загрузке страницы, если блок вне экрана.
- Задать: длительность анимации одного кружка, задержку между кружками (stagger delay), easing.

## 5. Анимация кнопок при наведении

- При hover на кнопку текст и иконка внутри неё слегка "разъезжаются" — увеличивается расстояние между текстом и иконкой (например, текст сдвигается влево, иконка вправо, или иконка сдвигается дальше от текста).
- Реализация: `transform: translateX()` на тексте и на иконке в противоположные стороны, с transition (~200–300ms, ease-out).
- Обязательно вернуть в исходное положение при `mouseleave` с той же плавностью.

## 6. Анимация изображений кейсов (превью)

- При наведении на картинку кейса изображение внутри рамки (фрейма) плавно увеличивается (`scale`), при этом сам фрейм (контейнер) **не меняет размер**.
- Реализация: контейнер с `overflow: hidden` и фиксированными размерами, внутри `<img>` с `transform: scale(1.05–1.1)` по hover и transition.

## 7. Сетка маленьких изображений (блок "Дизайны")

- В блоке с маленькими изображениями (постеры/мерч) при наведении картинка должна увеличиваться, **не меняя структуру сетки** и **не сдвигая соседние элементы**.
- Реализация: увеличение через `transform: scale()` (не через изменение `width/height`, не через grid-column/row), увеличенное изображение должно визуально "вылезать" поверх соседних — то есть на hover повышать `z-index` этого элемента, а сам скейл не должен занимать место в потоке (grid item сохраняет исходные размеры, скейлится только визуально).
- Добавить `transform-origin: center` (или в зависимости от позиции в сетке — от края, чтобы не вылезало за пределы экрана у крайних элементов).

## 8. Хостинг и домен

- Планируется покупка домена (название сайта) и хостинга — это стоит решить **до** начала кодинга или на самом старте, так как выбор влияет на стек и структуру проекта.
- Что нужно определить заранее:
  - **Домен**: где регистрировать (Reg.ru, Namecheap, Cloudflare и т.д.), какая зона (.ru/.com/.site и т.п.) — от этого может зависеть скорость и удобство привязки DNS.
  - **Хостинг**: статический (Vercel, Netlify, Cloudflare Pages — подходят, если сайт на чистом HTML/CSS/JS или React без бэкенда) или что-то с сервером/базой данных (если появится форма с бэкендом, CMS и т.п.).
  - Если сайт полностью статический (что вероятно для портфолио) — Vercel/Netlify предпочтительнее: бесплатны, просто подключают домен, автодеплой из GitHub.
- Попросить Claude Code сразу структурировать проект так, чтобы:
  - Все пути к файлам (картинки, видео, шрифты) были относительными или через переменные окружения — чтобы деплой на любой хостинг прошёл без правок путей.
  - Был готовый `README` с шагами деплоя (build-команда, куда пушить, как подключить домен).
  - Настроить проект под git-репозиторий с самого начала (даже если пока не хостится) — так проще потом подключить автодеплой.
- Решено: сайт переезжает с TapTop на отдельный код-проект (не Framer/TapTop) — значит, весь пункт выше актуален полностью, домен и хостинг нужно будет подключать отдельно от конструктора.
- Указать это явно в CLAUDE.md/промпте для Claude Code: сайт — самостоятельный код-проект (например, статический HTML/CSS/JS или React), без зависимости от TapTop; готовим структуру сразу под последующий деплой на Vercel/Netlify (или выбранный хостинг) и подключение купленного домена.
- **Структура папок**: отдельная папка под медиа, например `/public/media/` (или `/assets/`), с подпапками `images/` и `video/` внутри — не мешать медиафайлы с кодом компонентов. Указать это Claude Code явно на старте, чтобы он сразу так организовал проект, а не раскидывал файлы по разным местам.

## 9. Точность соответствия макету (pixel-perfect)

- Вёрстка должна максимально точно соответствовать макету в Figma: отступы, размеры шрифтов, толщина линий, размеры и позиции элементов — брать конкретные значения из Figma (через MCP: `get_variable_defs`, `get_design_context`), а не на глаз/примерно.
- Изображения, иконки и другие визуальные ассеты — брать реальные файлы из макета (экспортировать из Figma или взять через MCP), а не подставлять случайные плейсхолдеры/стоковые картинки, даже похожие по смыслу.
- Если какого-то конкретного значения (отступ, цвет, шрифт) не видно/не считывается через MCP — не придумывать его самостоятельно, а прямо спросить или пометить как "уточнить", вместо того чтобы подставлять близкое на глаз значение.
- После вёрстки каждой секции — сверять результат на localhost со скриншотом соответствующего фрейма в Figma бок о бок (можно приложить скриншот макета в сообщении Claude Code для сравнения).

## 10. Общие технические заметки

- Все transition/анимации — уважать `prefers-reduced-motion: reduce` (для доступности отключать/упрощать анимации).
- Видео на сайте (одно) — лениво подгружать, без автозвука, скорее всего autoplay muted loop либо по клику — уточнить.
- Ссылки на другие проекты — на buildin, ссылки на контакты — обычные внешние ссылки/mailto.
